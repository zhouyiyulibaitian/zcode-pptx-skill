# 自查清单与交付话术

## 交付前逐项过一遍

**结构**

- [ ] `validate` 0 error；warn 逐条判断是接受还是修
- [ ] 每页有且只有一个明确的论点；标题是结论句不是名词短语
- [ ] 目录/章节页与正文页的层级对得上（章节编号连续、没有孤页）
- [ ] 没有空页、没有只剩标题没有内容的页

**视觉**

- [ ] `shots` 出图后逐页看过（不是只看第一页）
- [ ] 无文字溢出、无元素互相遮挡、无贴边（正文与页边距至少留主题 `margin` 的 0.6 倍）
- [ ] 同类元素对齐：多页之间的标题基线、卡片间距尽量一致
- [ ] 满版图页的文字有足够的遮罩对比度（浅色图上白字 = 看不清）
- [ ] 图表有单位/口径，坐标轴标签没有被截断

**数据与事实**

- [ ] 图表数值与正文描述一致（"增长明显"就不要配一条下降的曲线）
- [ ] 外部数据标注了来源与年份
- [ ] 不编造调研样本量、百分比、文献数量

**备注（讲稿）**

- [ ] 关键页都有备注：讲什么、为什么、预计用时
- [ ] 备注是完整句子，不是把页面文字复制一遍

**成品**

- [ ] PPTX 打开后文字可编辑、图表可"编辑数据"、备注在备注页
- [ ] 给出的路径是绝对路径，文件确实存在且体积正常（不是 0 字节/几 KB 的空壳）
- [ ] HTML 预览能双击打开（相对路径的图片都在 `assets/` 里）

## 自查命令

```bash
S="<skill>/scripts/studio.py"
python "$S" validate --deck work/deck.json                 # 结构 + 溢出
python "$S" shots    --deck work/deck.json --pages 1,4-6    # 抽查关键页
python "$S" inspect  work/out.pptx --json /tmp/rt.json      # 回读导出结果，确认没丢东西
```

**回读验证**是便宜又有效的最后一道关：导出的 PPTX 再 `inspect` 一次，看页数、图片数、图表数、
备注数、`fonts_used` 是否与预期一致。数不对说明构建过程丢了东西。

## 汇报话术

说结果，说路径，说限制。例如：

> 做了 12 页，主题「深墨商务」。文件：
> - `E:\…\答辩.pptx` —— 可编辑成品（文字/图表/备注都能改）
> - `E:\…\deck.html` —— 预览，双击就能看
> - `E:\…\deck.json` —— 内容源文件，改完重新 `build` 即可
>
> 两点需要你确认：第 5 页的文献数量取自 CNKI 检索结果，口径是"主题检索 2021—2025"；
> 第 9 页表格里的三种规模分类是示例结构，需要你补上实际数据。

要主动说的限制：

- `to-deck` 转换是有损的（SmartArt/组合/媒体不转）
- `apply-template --mode layout` 时 HTML 预览与 PowerPoint 最终样式不完全一致
- 用了本机字体的地方，换电脑可能走样
- 占位图片（没有任何图片时画虚线框）需要用户替换

不要说的话：不要声称"完美还原""100% 保真""可以直接交"，除非真的验证过。
不要在没跑 `validate` 和 `shots` 的情况下交付。

## 用户改完之后的续做

用户在浏览器里改过 `deck.json` 后：

- 先 `validate` 再看 diff，不要假设用户的改法和你一致
- 用户可能把某一页 detach 成了显式元素（`detached: true`），这页不再跟随版式；
  要恢复版式驱动就把该页的 `elements` 删掉、重新给 `layout` + `content`
- 用户可能换了主题；重新 `render`/`build` 前读一次 `deck.json` 的最新 `theme` 字段
